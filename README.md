# БДЖ Мобилно Приложение - MVP Backend Модул (Фаза 1)

Това хранилище съдържа изходния сървърен код (**Backend API**) и автоматизирания инструмент за събиране на данни (**Scraper Worker**) от уебсайта на БДЖ за осигуряване на разписания и закъснения в реално време.

---

## 🛠️ Архитектура и Структура на Проекта

Проектът е изграден на **Node.js** и се разделя на два независими компонента:
1.  **API Сървър (`src/index.js`):** Обслужва клиентските заявки от мобилните телефони и чете бързо от Redis.
2.  **Синхронизационен Скрипт (`src/worker.js`):** Извлича данните ритмично през зададен интервал и ги съхранява централизирано.

### 📂 Файлова структура в генерираната директория:
*   `src/index.js` - Основният API сървър (Express.js).
*   `src/worker.js` - Скриптът за скрапване на данни от сайта на БДЖ.
*   `package.json` - Конфигурация на проекта и необходими софтуерни пакети.
*   `.env.example` - Шаблон за конфигурационни променливи (пароли, линкове).
*   `.github/workflows/deploy.yml` - Автоматизиран CI/CD тръбопровод за внедряване в реална среда.

## 🚀 Ръководство за Инсталация и Локално Стартиране

Следвайте тези стъпки на вашия компютър или сървър:

### 1. Предварителни изисквания
Трябва да имате инсталирани:
*   [Node.js](https://nodejs.org/) (Версия 18 или по-нова)
*   **Redis Сървър** (за бързото кеширане)
*   **PostgreSQL База данни** (за съхранение на статичните гари)

### 2. Инсталиране на пакетите
Отворете терминала в съответната папка на проекта и изпълнете:
```bash
npm install
```

### 3. Конфигуриране на Средата (.env)
Копирайте конфигурационния файл и въведете реалните си данни за базите данни:
```bash
cp .env.example .env
```
Отворете файла `.env` и редактирайте при нужда:
*   `PORT=3000` (Порт на който да работи API сървъра)
*   `REDIS_URL` (Адрес за достъп до Redis)

### 4. Стартиране на Компонентите

**Стартиране на уеб сървъра (за заявки от телефоните):**
```bash
npm run start
```

**Стартиране на скрипта за обновяване (Scraper-а):**
```bash
npm run worker
```

## 📘 Ръководство за Управление на Скрипта за Обновяване (`src/worker.js`)

Скриптът за обновяване е жизненоважният орган на системата. Ето как да го контролирате и следите:

1.  **Промяна на интервала на опресняване:** Отворете файла `.env`. Променливата `SCRAPE_INTERVAL_MS=60000` управлява времето на изчакване в милисекунди. За 1 минута стойността е `60000`. Не намалявайте стойността под `30000` (30 секунди), за да избегнете временна IP блокировка от страна на сървърите на БДЖ.
2.  **Защита при производствена среда (Production):** В реална среда скриптът трябва да се стартира чрез мениджър на процеси като `PM2`, за да се гарантира, че ако скриптът спре поради неочаквана грешка, той ще се рестартира автоматично:
    ```bash
    npm install pm2 -g
    pm2 start src/worker.js --name "bdz-live-worker"
    ```
3.  **Мониторинг на лог файловете:** За да проверявате дали инструментът събира успешно данните, използвайте командата:
    ```bash
    pm2 logs bdz-live-worker
    ```

## 🤖 CI/CD Автоматизация (GitHub Actions)

Вграденият файл във папка `.github/workflows/deploy.yml` позволява на всеки програмист автоматично да обновява производствения сървър. При всяко качване на код (**Push**) в централния клон `main`, GitHub автоматично:
1. Изолира кода в контейнер.
2. Проверява за синтактични грешки.
3. Подготвя пакета за качване на хостинг сървъра.
